# 历史案例：实际怎么组合的

每条记录一个已完成案例：当时的任务约束、选了哪些能力、为什么、代价、结果，以及事后回看有什么可以不同。它们是那个任务的解，不是模板。借鉴前先对照约束：约束不同，解就该不同。

项目目录在 `$MG_WORKSPACE/projects/<日期>-<slug>/`，成片与联系表在 `$MG_WORKSPACE/effects/renders/`。

## 同一主题、三种约束、三条路线

“图书馆等轴生长片”做了三次，每次约束不同，组合也不同。这组对照最能说明为什么没有固定配方：

| 案例 | 约束 | 组合 | 结果 |
|---|---|---|---|
| library-iso（2026-10-20） | 只有一张带透视的参考轴测图 | Canvas2D 轴测画家算法 + numpy 配乐音效 | 投影只能设定，右翼与参考差约 50 px；38 个卡点 ≤1 ms |
| arc-axo（2026-10-20） | 6 张同构图关键帧，环境不动 | 空地关键帧作底图 + Canvas2D 只画建筑与人群 + numpy 音频 | 投影按关键帧实测标定，外轮廓误差几个像素；底图里画死的人要先抹掉，车辆只能静止 |
| library-3d（2026-10-20） | 用户要求先 3D 建模 | Blender 脚本建 930 个部件 → three.js 正交渲染（三档着色器 + 描线）+ numpy 音频 | 450 帧 0 穿插、逐帧测角 ≤0.33°；模型可交付；测角工具未校准导致全片做完才重标 |

## 逐案记录

### make-it-move（2026-09-27）
- **任务**：15 s 1080p60 MG 作品集样片：动态字体、几何变形、金属环雕塑。
- **组合**：Python numpy/PIL 逐帧 → ffmpeg；numpy 原创电子配乐。
- **当时的理由**：60 fps、逐像素控制，雕塑可以解析光栅化，不需要浏览器。
- **代价**：免费。
- **结果**：成片 + 配乐卡点信息输出到 `audio-info.json`。

### katana-face-edit-2（2026-10-10）
- **任务**：复刻 Higgsfield Katana 换主角歌词 MV（13.3 s）：歌词在头后、HUD、热成像闪帧、故障爆发。
- **组合**：Seedance 2.5 底片 → 抠像 matte → numpy/PIL 逐帧合成文字、HUD、故障。
- **当时的理由**：真人主角只能生成；图形和时间交给代码，便宜且可精确到帧。
- **代价**：付费前完整逐帧分析参考片，发现“21 个 cut”实为单镜头加叠层，成本降到 172 credits。
- **事后看**：先免费分析、再核价付费的顺序值得保留。

### let-me-paint（2026-10-16）
- **任务**：26 s 双角色旁白短片，从规则驯化的速写到厚涂日出。
- **组合**：Remotion + Canvas2D + WebGL 程序化厚涂；已有配音按静音与基频对齐成时间轴；numpy 合成音效与配乐。
- **当时的理由**：画风本身就是“程序化笔触”，旁白驱动节奏。
- **结果**：沉淀了厚涂、手绘线、字体加载、静帧审片等可复用代码。

### fw26-lookbook（2026-10-19）
- **任务**：重制 Katana 预设 12.2 s 时装 lookbook：鱼眼街拍、圆形遮罩、分屏、划变、甩镜、闪白。
- **组合**：Soul Cinema 场景底图 + 3 条 Seedance 2.5 底片（分权 header + 5 段 2 秒镜头表）+ ffmpeg EDL 合成。
- **当时的理由**：鱼眼、手持、甩镜靠三维视差，写进生成 prompt；遮罩、HUD、划变、闪帧便宜可重做，放进合成。Katana session 只有 1 小时，内置合成器来不及，改用 ffmpeg。
- **代价**：3 条共 30 s 底片切出 27 镜。
- **事后看**：闪白闪黑次数应按参考片能量图实测（参考 7 白 5 黑，v1 只做 3 白 2 黑）。

### bell-machine（2026-10-20）
- **任务**：14 s 1080p60 连锁机关，一推到底砸响铜钟，撞击卡用户给的配乐鼓点，不剪辑不变速。
- **组合**：planck.js 真物理（逐环调参 + 拦截法）→ 烘焙 → Remotion/three.js 渲染 → 接触事件驱动程序化音效；配乐不动，只压音效总线。
- **当时的理由**：“过程本身成立”是硬约束，先写验收（拦截施力接口证明只有一次外力、卡点误差表），再选路线。
- **结果**：38 次撞击 ≤2.5 ms；配乐相关系数 0.99965。

### city-love（2026-10-21）
- **任务**：按参考片同骨架换主题的 20 s 混合媒介 MG：热成像人像、墨迹吞噬、像素体素、逐词旁白、逐拍卡点。
- **组合**：3 条 Seedance 2.5 底片（剪影、手、墨迹）→ numpy 离线热成像与墨团序列；Remotion + three.js 体素；ElevenLabs 旁白（按能量谷切逐词）；numpy 配乐音效。
- **当时的理由**：先给每个元素标“生成 / 代码 / 生成素材库 / 人工”，再谈价格；身体动作和有机墨迹交给生成，一条 6 s 墨迹素材拆成墨团库全片复用。
- **代价**：5+6+6 s 实扣 1327.62 credits（估算 1300）。
- **事后看**：“像原片”靠骨架（段落、配色、拍子网格、粘合层），不靠单个特效。

### b612-slice（2026-10-22）
- **任务**：25 s 3D 短片：原创小王子风格小女孩在小星球上环游，看玫瑰、看落日，一镜到底。
- **组合**：生成设定图 → Tripo 角色（四边面 + 自动绑骨 + 预设动作）与有机道具 → Blender 程序化场景（草地、云海、落日）→ EEVEE 渲染；百炼童声台词；MiniMax 纯音乐。
- **当时的理由**：会走动的角色和靠光照成立的场景，three.js 难达到；每张生成图先当规格给用户确认。
- **结果**：资产每项一两次就过，场景和镜头迭代了 15 轮。
- **事后看**：质感跃迁主要来自光照与渲染管线，而不是换模型；剩下的短板是动作和材质。生成资产写实材质偏塑料，这次以风格化渲染（卡通分层 + 描边）收尾，用户认可；写实只在 Cycles 关键帧上验证过。

### saas-launch-v1 与 saas-launch-v2（2026-10-23）
- **任务**：同一产品的约 2 分钟发布宣传片，两个模型各做一版。
- **组合**：按 demo 重建 DOM、直接复用 demo CSS（Remotion）；MiniMax music-2.6 配乐；百炼男声旁白；numpy 程序音效。
- **当时的理由**：有可运行的 demo，重建能做到像素一致、任意特写与推拉、每帧可复现；录屏的节奏与画质不可控。
- **事后看**：
  - 先拿到配乐、实测节拍再排分镜（生成音乐的 BPM 不听 prompt）。
  - Fable 版用了跨帧 React 状态 + 计数 guard，并发渲染下出现 4.5 s 乒乓帧；静帧和联系表都测不出，需要 `pingpong.py`。
  - 浅色产品配浅色大字场景，镜头在字幕与界面间切换不会亮度硬跳；开场冲突要直指产品核心主张。
  - 同题对比时后跑的一方读了先跑的产出，对比不再同条件。

### marunouchi-lyric 系列：同一首歌四版（2026-10-23 – 10-24）
- **任务**：椎名林檎《丸ノ内サディスティック》整曲 3 分 56 秒歌词 MV，以歌词为画面主体，音频不做任何处理，风格与工具由 Agent 自定。用户看完一版提一次更深的要求：v1 之后说「像一个简单的歌词展示器，情绪和画面都缺少表达」；v3/v4 要求彼此、并与前两版有明显视觉差异，隔离旧代码，中途追加画面贴合深层内涵、不做逐句字面联想。
- **组合**（四版都在 Remotion 里，都用 ffmpeg 流拷贝封装源 FLAC，另出 MOV + ALAC）：
  - v1：DOM 排版 + SVG 线路 + Canvas2D LED 点阵；lrclib 同步歌词给行首、ASR 作锚点核对、频谱通量 DP 节拍跟踪给拍与小节线。母题取自歌词专名（地铁站名、乐器、領収書）。
  - v2：逐句字义物件（DOM / SVG）+ DOM 底下全屏 WebGL 片元着色器做烟、光斑、红光 + 手写段落情绪曲线 + 逐帧音频特征做细节呼吸。
  - v3「赤字」：SVG 出纳帐逐拍记账 + 红墨手写，用位移 + 模糊 × 纤维噪声做洇开。
  - v4「一根光」：Canvas2D。每帧真实波形 + 字形单线骨架的霓虹灯管 + 光图 × 墙面反照率的光照与湿地面倒影。
- **当时的理由**：歌词要逐字精确、与实测时间同步，日文混排是排版问题；生成视频会让文字失控、抢走主体，还要付费。v2 起情绪靠弧线和画面，有机氛围交给着色器；v3/v4 在媒介（纸墨 / 光）、密度（累积 / 写完即灭）、音乐角色（驱动节拍 / 画面本身）上取相反端，各用一个能同时装下歌的几层关系的隐喻。
- **代价**：免费。236 s 全片渲染约 2 分 40 秒到 4 分钟（并发 6，见 A1 代价）；每版静帧审片 1–2 轮。v3/v4 有约四分之一时间花在 headless Chrome 不出帧的环境故障上。
- **结果**：四版音频解码 PCM 与源逐采样一致。用户 2026-10-23 确认 v2 为当时的最终交付；v3/v4 未做人耳试听和用户审片。
- **事后看**：
  - 表达深度是逐版逼出来的：v1 排版做对了但没有画面；v2 有了画面，但仍是逐句按字义配图；v3 最初的剪贴 zine 方案也还是字面联想，被用户纠正后才转向整首歌的内涵。判据见 craft-lessons L5 与 task-lenses 第 8 问；v2 开工时没重新加载本手册、没给分工表（L6）。
  - 歌声 ASR 不能当时间轴；摇摆曲上高频起音会估错 BPM；母带压得满时段落能量差很小，弧线要手写（见 G2 边界、pitfalls 的 TTS / 音乐 / 混音组）。

### code-to-cinema（2026-10-24）
- **任务**：75 s 1080p30 能力巡礼片，主题“Opus 5.5 只写代码产出视频”，尽量串起手册里的能力，同时验证当天写进手册的 effects、着色器转场与剪辑语法；选择不付费。
- **组合**：Remotion 总合成（HtmlInCanvas 终端、18 种 effects、7 种着色器转场、captions）+ HyperFrames 标题底片 + planck 按拍落键 + three.js 体素通道 + Blender EEVEE 四类底片（主镜头、遮罩、晃动、12 fps 绿幕）+ numpy D2 遮罩合成 / 后期实验室（vidstab、颜色跟踪重构图、Lab 迁移 LUT、minterpolate 坡道）+ numpy 雕塑 + anatomy 剪辑台经 CDP 实时录屏 + macOS say + music_kit 程序配乐。
- **当时的理由**：后期手法需要可控的输入才能测出数字，于是用 Blender 自产“实拍”；每章对应一张能力卡，左下角标签直接标卡号。
- **代价**：免费；Blender 底片约 10 min，全片渲染 298 s；配乐平衡调了 6 轮。
- **结果**：-14.8 LUFS / -1.5 dBTP，乒乓帧 0 段，落键 ≤1 ms；D5–D7、G5、A2、A4、A5 升级为案例验证。
- **事后看**：配乐应先定各总线电平再写音色；`<CameraMotionBlur>` 写进分工表后没有落地，收尾要对着分工表逐项对账。

### deepseek-no-camera（2026-10-24）
- **任务**：90 s 回应式预告片，主题“谁说只有 Opus 5.5 可以出视频”；约束是不参考任何既有案例，只用能力卡与工艺经验；允许少量付费生成。
- **组合**：生成底片（尘 / 墨，24→120 fps 补帧后按速度曲线取帧）+ three.js 百叶光带与 clay/wire 三通道 + HyperFrames 逐字主张 + numpy 差分 matte / 双色调 / 文字在墨后 + 程序化蓝图与源码滚动 + numpy 程序配乐，2.39 遮幅在片尾撤成全幅。
- **当时的理由**：论点要“专业”而不是“能力罗列”，所以先立一个只有摄影机能拍的镜头，再一路拆给它看；片尾撤遮幅、露出本片源码，用画幅本身完成论证。
- **代价**：Blender 光段迭代 3 版全废（无百叶光带、玻璃读成纸板、道具陷进桌面）；换 three.js 后同镜头一次立住；全片渲染并发 2、约 7 分钟。
- **结果**：-14.0 LUFS / -1.2 dBFS；最长静止段 7.67 → 4.33 s；乒乓帧告警经逐帧复核为抽样误报。
- **事后看**：第一次 Cycles 出图“零阴影 + 墙面比桌面亮”时就该判定主光没进画并换路线；生成素材明暗关系反了时，应先改拍法而不是先写 lumekey。

### lensless（2026-10-30）
- **任务**：120 s 发布片格调短片，主题“谁说视频一定要有一台摄像机”；要求工具与效果尽量多、≥3 段生成素材、配乐 + 少量女声旁白 + 音效；用户要求按独立任务做、不参考既有产出。
- **组合**：Seedance 2.5 静音底片 ×4（微距、液态金属、FPV 航拍、慢动作人像）经 MediaKit fast 到 1080p、光流补成 60 fps 序列，画面按“源时刻”取帧并相邻帧叠化 + WebGL 光追着色器（图块显影、噪点收敛）+ three.js 点云碎裂 + HyperFrames 主张 + numpy matte / 像素排序 / 线稿 / 字符画 + Blender EEVEE 镀铬落版 + 生成配乐 + TTS 旁白 + numpy 事件音效。
- **当时的理由**：论点由画面来源本身承担，“拍得到的”交给生成，“算出来的”交给代码；配乐先生成、实测出三个能量台阶（33 / 76 / 114 s）后，把段落写成拍号，不剪改配乐。
- **代价**：付费 1901.75 credits，全部一次成功；全片并发 3 渲染约 6 分钟。
- **结果**：-13.8 LUFS / -1.2 dBFS；乒乓帧 0；成片 ASR 6/6 句；未人耳试听。
- **事后看**：慢放段源速度低于 1 帧/输出帧时要叠化相邻帧，取整会出重复帧；配乐的能量结构比分镜更早决定段落长度。

### llm-launch-agate（2026-10-31）
- **任务**：coding LLM 宣传片。第一版 100 s 暗场炫技（实拍检索 + 代码流 + WebGL + 跑分占位）被用户判「言之无味」；拆解 Kimi K3 发布片后按其形式复刻 45 s，素材全换、全程免费。

- **当时的理由**：版本号「5.5」恰是传统活字 Agate 的磅数（最小仍可读、专排数据表），意念与材料同时成立；剪辑吸附实测乐句起点。
- **代价**：免费；45.5 s 渲染约 2 分钟 / 次，5 轮。
- **结果**：亮度中位 214、饱和度中位 0.06（参考片 193 / 0.06，第一版 10 / 0.29）；-21.5 LUFS、LRA 8.9；乒乓帧 0；未人耳试听，用户未评价。
- **事后看**：第一版缺的是意念不是技术；档案素材要先统一进同一种纸面色调，混搭才不像拼贴。

### idol-trailer（2026-11-03）

### claude-showreel（2026-11-07）
- **任务**：15 s 1080p60 自荐 showreel，用户只给一句要求，全程序化，无付费。
- **组合**：单页 HTML：可变字体 DOM + Canvas2D + WebGL2（片元路径追踪柱阵、逐波长折射玻璃、52 万闭式粒子），自写时间超采样采集器 + 线性光累加；numpy 配乐。
- **当时的理由**：字和卡点要逐帧精确；二维圆盘要无缝变成三维球，2D 与 3D 得同一坐标；`--fps 240` 每帧样本太少。
