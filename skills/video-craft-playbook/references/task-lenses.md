# 选型透镜：从表达需求到能力分工

这里没有决策树。决策树会把选择固化成公式，而同一类片子在不同约束下的合适解完全不同。下面是一组问题和权衡轴，帮你针对当前任务做有目的的选择。

## 一、逐元素提问

先把成片拆成元素（主体、环境、运动、镜头、文字与图形、质感、声音、节奏），对每个元素问：

1. **它的“真”从哪里来？** 观众凭什么相信它：
   - 身体动作、手、实拍质感、三维视差 → 来自真实拍摄或生成视频。
   - 物理过程（碰撞、倒下、滚动） → 来自模拟，过程要真算。
   - 光照质感（GI、软阴影、毛发、云） → 来自有全局光照的渲染器。
   - 品牌或产品的像素一致 → 来自产品自身的代码和样式。
   - 数据、文字、排版 → 来自代码精确绘制。
   - 手作感、笔触 → 来自程序化笔触，或生成的笔触库。
2. **要不要逐帧精确？** 卡点、对齐、可复现、任意帧可单独重渲。越需要精确，越要考虑确定性高的能力，或把不确定的部分限制成素材、由确定的一端掌控时间。
3. **会改几轮？谁来改？** 前期成本与每轮修改成本的比例决定性价比：写代码前期贵、每轮便宜；生成前期便宜、每轮重抽要付费且结果不可控。
4. **能不能付费、预算多少？** 付费能力先报价、经用户确认；不要因为要付费就把只有生成能做好的元素硬塞给代码，也不要为省事把代码能精确做的元素交给生成。
5. **多快要出片？渲染耗时多少？** 先测一次单帧或短段耗时，再决定迭代粒度（全片草稿还是逐镜头）。
6. **画风靠什么成立？** 对照 `$MG_WORKSPACE/effects/styles.md` 的“成立条件 / 退化成”判断哪种能力能满足成立条件。全片是不是一套画风、一套色板、角色走哪条路，开工前写成三行锁住（craft-lessons L54）；要迁移某位艺术家或某个工作室的画风时见 craft-lessons L58，并先查同一文件末尾的“艺术风格”分组（A01–A37：36 种艺术家 / 时代画风的成立条件、画材做法、母题动作、签名转场、已知短板，外部蒸馏、本机未做过）。
7. **有没有现成素材或参考？** 用户给了 demo、关键帧、参考片、配乐、模型，往往直接决定某个元素该由谁来消费这些输入。有真实的截图、照片、录像、原文、产品产出时，它们就是主画面，满幅放，代码负责解释、标注和运镜；只有真找不到素材的段落才整页代码画或生成（外部 huashu-art-motion：一支几乎全生成的技术长片被作者判观感差）。给了参考片时先问还原度：“复刻”照原样保留节拍、文案、构图、配色；“同款换成我的品牌”保留形式、只换点名的内容，含义只对原品牌成立的段落按同样形式重写，或删掉、时长让给相邻段（外部 OpenDesign Motion）。
8. **情绪在全片怎么变化？** 有叙事或歌词的片子，先写一条随段落变化的情绪 / 热度弧线，再看每个元素在弧线上处于什么位置；每段都用同一套出现—停留—退场的模板，会被看成信息展示而不是影像。母带压得很满的歌，段落间能量差很小，弧线要手写。歌词片还要问：这个画面换一句歌词还成立吗（craft-lessons L5）；先把歌的几层关系写清，再找一个能同时装下几层的媒介隐喻（例：「赤字」同时是亏空、红笔改稿、血色）。（marunouchi-lyric 系列，2026-10-24）
9. **每一镜画面里能指着说“就是它”的物是什么，它在做什么？** 写不出物的那一镜先别做；抽象概念要找一个具体的物来演，不只写成字和图标。镜头表写法、开头结尾、文字镜头占比的参考线见 lessons-backlog L61（外部 huashu-art-motion，候补）。
10. **这段旁白在做哪种解释动作？** 讲机制、讲尺度、有出处的论证、推导链、第一人称经历、清单金句、产品教程、数字走势，各有一种成立的画法与节奏；同一支片可以分段换，同一段不混，全片最多两三种。对照表见 [editing-grammar.md](editing-grammar.md) EG-70–EG-77。
11. **这个元素是“做出来”还是“找得到”？** 对每个元素走一遍来源阶梯：用户自有 / 本地素材（H2）→ 开放素材库（H1）→ 生成（C 组）→ 代码画（A / B 组）。阶梯是检查顺序，不是排名：找到的素材便宜、可信、上镜的是现实世界，但只能挑不能改；生成可控主体但付费且要审片；代码精确但没有实拍质感。操作演示、产品本身、本人出镜只能来自本地；人群、城市、自然、天气这类“世界的镜头”常常找得到；带品牌、特定动作、要与文字图形精确配合的镜头才落到生成或代码。全代码或全生成的片子缺信服力时，先问有没有一镜真实画面可以插进来。找之前先把文案翻成可检索的镜头描述（craft-lessons L60）。（外部 asset-discovery，2026-10-30 收录）
12. **这支片只讲哪一个意念？名字或版本号本身能不能就是主题？** 先写一句「它是什么」的隐喻，再拆元素；写不出时，每个元素都会退化成罗列能力（计数器、跑分、能力卡），看起来强、说不出东西。检查名字、版本号、产品术语在别的领域里是否已有含义，能借来当母题。（llm-launch-agate：第一版被用户判「言之无味」，复刻版借「5½ 磅 = Agate」成立，2026-10-31）
13. **第一反应是不是模型的默认答案？** 动手前写下最先想到的概念、母题和版式，再问：换个模型、或者不看这本手册，会不会也这么做。会，说明它来自模型先验，而不是这条片子的选择；要保留得说出理由，否则换掉。已观察到的默认：圆点当主角并落成句号、四角 HUD 与分段编号、“每一帧都由代码生成”一类声明、128 BPM。（Opus 5.5 在无手册的 10-05 与有手册的 11-07 两次独立收敛到同一套，GPT-6 Astra 09-27 也用了 HUD 与分段编号；claude-showreel 对比评估，2026-11-07）

## 二、权衡轴

每种能力都在这几条轴上占一个位置（数据见 capability-atlas 各卡）：

| 轴 | 一端 | 另一端 |
|---|---|---|
| 控制 ↔ 自然度 | 代码精确控制，但有机感、身体感难做 | 生成或模拟带来自然感，但细节难控 |
| 确定 ↔ 惊喜 | 每次结果一样，可回归验证 | 每次不同，需要挑选 |
| 前期成本 ↔ 每轮成本 | 搭建贵、修改便宜 | 搭建便宜、修改贵 |
| 时间 ↔ 金钱 | 本地渲染耗时 | 付费调用省时 |
| 交付物形态 | 只要视频 | 还要交付模型、工程、可编辑源文件 |

一个元素在轴上的需求，和某个能力在轴上的位置对得上，才是有目的的选择。

## 三、拼接接口（多种能力组合时先定）

组合越多，接口越要先定好，否则后期对不齐：

- **时间权威**：所有时刻从一个来源派生（`timeline.json` 或常量表），画面、音频、字幕只读它。生成素材的时机不受控时，用后期变速对到时间权威上，而不是反过来改时间轴迁就素材。
- **帧率**：生成视频常是 24 fps，合成端若是 30 fps，按 `round(f*24/30)` 映射；拼接时按帧号重写时间戳。
- **坐标与相机**：2D 叠层跟 3D 物体时，投影参数和相机必须同源；叠层跟 DOM 元素时，按渲染后的实测矩形定位。
- **alpha 与 matte**：在生成阶段就设计好可抠的背景和光；离线合成成序列帧，比运行时遮罩稳。
- **色彩**：three.js 颜色管理、Blender 的线性像素、ffmpeg 色彩空间各自不同，跨端前先单帧对色。
- **音频总线**：配乐、旁白、音效分轨；用户给的配乐保持原样，只压音效总线；响度在编码后的成片上测。
- **体量权威**：同一个几何体被多个渲染端使用时，让一个脚本（例如 Blender 建模脚本）同时导出所有端需要的格式。

## 四、能力分工表（开工前写出）

在第一条回复里给用户看，然后执行。每个关键元素至少写一个被比较过的替代，证明这是有目的的选择而不是套公式：

```markdown
| 元素 | 选用能力 | 为什么（对应哪个问题 / 哪条轴） | 比较过的替代与放弃原因 | 验收方式 |
|---|---|---|---|---|
| 人物伸手入镜 | 生成视频（C1） | 身体动作的“真”只能来自拍摄或生成 | 程序化 3D 角色：动作库没有，自做成本高 | 逐张联系表看手指解剖 |
| 标题与字幕 | 程序化画面 | 要逐帧精确、跟旁白逐词出现 | 生成视频带字：文字不可控 | 静帧 + 成片 ASR |
| 城市夜景航拍空镜 | 开放素材库检索（H1） | 世界的镜头，找得到就不必生成（第 11 问） | 生成视频：付费、航拍视差不稳；代码：没有实拍质感 | manifest 许可核对 + 调色匹配后看联系表 |
| … | | | | |

拼接接口：时间权威 = …；帧率 = …；坐标 = …
付费项与预算：…（待用户确认）
外来素材与许可：…（`assets/manifest.json`；每条来源、作者、许可证）
会让我改变分工的信号：…
```

“会让我改变分工的信号”写具体的可观察现象，例如“生成的手两次都出现手指粘连”“单帧渲染超过 30 s 导致迭代太慢”“用户要求交付可编辑模型”。

## 五、执行中重新评估

分工不是一次定死。出现下面的情况时回到第一节重新问：

- 某个能力的实际表现和能力卡描述不符（这也是回写素材）。
- 约束变了：预算、时长、交付形态、用户新给了素材。
- 验收一直不过，且问题根源在能力本身的边界，而不是参数。

## 六、剪辑类任务的补充提问

素材已经给定（实拍、录屏、已生成的片段），主要工作是剪辑和后处理时，在第一节之外再问下面几条。手法见 [editing-grammar.md](editing-grammar.md)，信号见 [edit-signals.md](edit-signals.md)。本节为推断（2026-10-24 收录），待剪辑案例验证。

1. **素材能不能补？** 只能用现有素材，还是可以补拍或再生成？缺口靠剪辑手法填（推镜、B-roll、定格），还是靠补素材填，两种路线的成本完全不同。补素材有三级：本地素材库（H2）、开放素材库检索（H1）、补拍或再生成。
2. **这条片子放大哪种信号？** 信息（口播）、节奏（音乐）、动作高光，还是情绪？它决定切点吸附到词边界、节拍还是动作，每个段落选一个主导来源。
3. **交付到哪、什么画幅？** 横竖转换要不要跟随主体重构图；字幕和图形要避开哪些平台界面区域；开头几秒怎么设计。
4. **同一内容有没有多遍、多机位？** 有，就有择优和机位切换的空间；没有，跳剪只能靠推镜放大交替或 B-roll 覆盖。
5. **素材之间质感差多大？** 多来源、多批次生成的素材，先做画质修复与调色匹配，再谈风格 look 和特效。
6. **哪些信号能可靠拿到？** 先跑理解，看 edit-signals 各字段的覆盖率和置信度。信号缺失或不可靠，就不用依赖它的手法（例如主体轨迹抖，就不做跟随重构图）。能力分工表里给剪辑元素多写一列“依赖的信号”。
7. **原声能不能动？** 现场声、旁白、音乐分别能不能剪、降噪、加音效；用户给的配乐保持原样（第三节音频总线）。
8. **交付成片还是可编辑的时间线？** 需要后续改的，把决策写成独立的时间线数据（切点、变换关键帧、转场与动机、效果栈、音频分轨、字幕），渲染端只读它。 多轮迭代的叙事片尤其要留音频分轨：下一版只能继承成品混音时，删句、声音先入和静默都做不干净，这项工作常到改稿之后才暴露；没留分轨时看 atlas E2。（qingniang-v4-audit）
