# 工艺经验（跨工具成立）

从历史案例里提炼的、换工具换路线也成立的做法。每条标来源案例；完整推理与数据在 `$MG_WORKSPACE/effects/methods.md`（括号里的 M 编号对应该文件条目）。标“外部 huashu-art-motion”的内容取自 [huashu-art-motion](https://github.com/alchaincyf/huashu-art-motion) v1.2.0（2026-10-26 收录）的实测数字与作者评片，作者的品味不等于本机用户的品味，且本机未验证；本机案例验证或推翻后改标案例。标“外部 OpenDesign Motion”的内容取自 [nexu-io/open-design](https://github.com/nexu-io/open-design) v0.25.0 的 motion skill 与源码（2026-10-29 收录），是流程与设计主张，不是实测；标“外部 deepseek-opus-motion-skill”的数字是 [该仓库](https://github.com/8533502-dev/deepseek-opus-motion-skill) 作者自测。标“外部 asset-discovery”的内容取自一位抖音创作者 2026-10 的视频（同一模型做动效、有无真实素材的成片对比，以及他的找素材 skill `asset-discovery` 的流程演示；2026-10-30 收录），是流程主张与许可对照，本机未验证。

`L` 编号是稳定 ID：其他文件用「craft-lessons L5」引用；删除或合并条目后编号留空洞，不重排；新条目取当前最大号 +1。分组只决定阅读位置，不决定编号。

每条标题后带一个标签：`〔通用｜阶段〕` 指任何 vibe motion 都适用，`〔条件：标签｜阶段〕` 写它在什么体裁、工具或素材下才适用；阶段（规划、执行、审片、交付）写它该在哪一步被照做。组内通用条目在前。按阶段和标签取条目用 `playbook.py brief --phase <阶段> --tags <标签>`，它也会列出 [lessons-backlog.md](lessons-backlog.md) 里命中的候补条目；规则见 [writeback.md](writeback.md) 第一节第 4 条。

## 一、立项与验收

- **L1 先定义“怎么证明”，再选路线。** 〔通用｜规划〕 要求过程本身成立的片子（真物理、卡点、不剪辑、不变速），先把验收写成可执行的检查（核验脚本 + 误差表），肉眼看片只作辅助。（bell-machine，M1）
- **L4 人工门放在主观且便宜的环节，机器门放在可量化的环节。** 〔通用｜规划〕 画风、服装、气质让用户逐张确认；面数、尺寸、姿势写成自审脚本放行。问题在最上游能发现的地方修，修改成本沿管线递增。（b612-slice，M50）
- **L6 迭代版本按新案例处理。** 〔通用｜规划〕 重新跑 `playbook.py status`、在第一条回复给出能力分工表；用户要求丢掉旧方案时，只沿用事实性数据（测量的时间轴、节拍、交付规则），不沿用旧版组件与母题。（marunouchi-lyric-v2）
- **L2 硬约束翻译成“自由度挪到哪里”。** 〔条件：物理｜规划〕 运行中不许干预，就把调节全部挪到运行前的参数上，每次从 t=0 整段重跑。（bell-machine，M2）
- **L3 可行范围里没有目标时换变量或换机构，别硬调。** 〔条件：物理｜执行〕 信号：搜索找不到括号，或参数被推到区间边界。（bell-machine，M4）
- **L5 歌词 MV 的画面要承载整首歌的内涵，不做逐句配图。** 〔条件：歌词MV｜规划〕 去掉行号、时间码这类播放器外壳；每句套同一个出现—停留—退场模板，会被看成「歌词展示器」。定画面前先做「换一句测试」：只对这一句成立的是字面配图，只适合作点缀；主画面要对整首成立，只随段落情绪变化。歌词字本身，决定性的是字体和位置：挂到画面里的物上，不浮在画面中央。例与细节见 lessons-backlog L5 细则。（marunouchi-lyric → v2 → v3v4；idol-fx-mid v3）
- **L7 参考片先转成可执行的规则再动手。** 〔条件：复刻｜规划〕 配色、字号、镜头时长、进出场顺序、拍子网格写进项目 README 或 PLAN；“像原片”靠骨架，不靠单个特效。按某类型片（Vox、白板、storytime 一类）的语法做时，先拿 2–5 支代表作实测，印象里的“风格特征”常常不对。时间轴靠测量不靠目测，切点只是线索。规则冲突时按“测到的 > 用户对参考片说的保留与改动 > 自己的审美”取舍。量法与数字见 lessons-backlog L7 细则。（city-love，M39；外部 huashu-art-motion、外部 OpenDesign Motion）
- **L59 让较弱或便宜的模型做动效，要补的是做事方式，不是审美。** 〔条件：弱模型｜规划〕 审美放进三处：一组用代码重建、质量已被认可的样片作起点；写成条目的规则（时长区间、“问题 → 改法”对照）；写死的渲染与校验（时钟、画幅、音轨由宿主检查）。长提示词逐条建账：每个数值、每个“A 变成 B”、每个要画的元素编号落进代码，后三分之一和前面一样作数。越依赖角色表演与叙事光线，规则补得越少。外部对比数字见 lessons-backlog L59 细则；本机未做同题 A/B，做时按 L50。（外部 OpenDesign Motion、外部 deepseek-opus-motion-skill）

## 二、时间与确定性

- **L8 时间单一权威。** 〔通用｜规划、执行〕 切点、事件、旁白逐词时刻都从一个来源派生，画面和声音只读它；代码里不写散落的绝对秒数。跟口播走的事件写成“念到哪个词”，渲染前再换成帧，口播一改就拒收而不是悄悄错位。要“只改一处”时，配置里同时放时钟（场景时长首尾相接加 cue）和可替换内容，用户可能点名的元素带稳定 id。结构与实测见 lessons-backlog L8 细则。（library-iso、city-love，M16、M41；外部 huashu-art-motion、外部 OpenDesign Motion）
- **L9 画面是 t 的纯函数。** 〔通用｜执行〕 任意一帧都能单独渲染，随机数带种子。并发渲染会把帧乱序分给多个页面，任何跨帧保留的状态（缓存、计数 guard、“上次结果”）都会导致逐帧抖动。（saas-launch-v2，M65）
- **L10 模拟和渲染分离。** 〔条件：物理｜执行〕 模拟 → 烘焙成逐帧数据 → 渲染端只读；核验时把重跑结果与烘焙数据逐帧比对。（bell-machine，M9）
- **L11 画面派生音频，数据单向流动。** 〔条件：音效｜执行〕 画面模型算出每个音效事件的时刻、强度、声像 → 写成事件表 → 音频脚本只读事件表。画面一改，音频按顺序重跑就自动对齐。（library-iso，M16）
- **L12 生成素材的时机不受控时，用变速对齐时间权威。** 〔条件：生成｜执行〕 动作描述只当方向，真正的时机用分段变速重映射到事件点。（city-love）

## 三、生成与代码的分工

- **L13 生成端负责“镜头能拍到的”，合成端负责“图形和时间”。** 〔条件：生成｜规划、执行〕 判断标准：这个效果靠不靠三维视差或身体动作。鱼眼、手持、甩镜、伸手入镜写进生成 prompt；遮罩、HUD、文字、分屏、闪帧、调色留给合成。生成端漏写的镜头语言后期补不回来。静帧上用代码做物理运动（闪电、门缓慢打开、电光聚形）会被一眼判假，改图生视频。（fw26-lookbook，M36；idol-trailer v2，M79）
- **L14 先分工，再谈成本。** 〔条件：生成、付费｜规划〕 每个元素先判断“生成 / 代码 / 生成素材库 / 人工”，再按价格取舍。（city-love，M40）
- **L15 生成素材当素材库用。** 〔条件：生成｜执行〕 一条 10 s 视频按每 2 秒换机位写，可切出 5–8 段；一条墨迹扩散素材可拆成带 alpha 的墨团库全片复用。拿到底片先按秒标可用区间。复用有上限：同一动作镜头换不同后处理反复出现会被看穿（一个踢腿镜头 6 次，导演判「效果不行」），排剪辑表时按素材数出现次数，超过 2 次要有理由，否则补生成。（fw26-lookbook、city-love，M37；idol-trailer v3，M78）
- **L16 参考图分权：每张图只管一件事。** 〔条件：生成｜执行〕 用户图只管身份和服装（逐件列出），场景图只管环境。（fw26-lookbook，M37） 要保留参考图的姿势时 prompt 只写“保持参考图里的手势”，写出动作（“端杯喝茶”）会压过参考图；毛色、配色写到部位，只写“橘猫”会画成全身橘。（外部 huashu-art-motion）
- **L17 生成关键帧只生成能被代码直接消费的那几张。** 〔条件：生成｜规划〕 空地底图、同机位落成图值得生成；爆炸图只作布局参考；生长过程图由代码推出更一致；时间不画在图上。分层素材用设定帧当参考图，要求“只画参考图里的某物，其余纯平涂绿幕，位置大小朝向不变”，生成出来就站在原画面坐标上；抠图时记下左上角偏移，合成按原坐标贴回。（arc-axo，M33；外部 huashu-art-motion）
- **L18 每张生成图先当规格审，再往下游走。** 〔条件：生成、3D｜审片〕 服装要为绑骨服务，在出图阶段改比在 3D 阶段修便宜。（b612-slice，M44）
- **L19 生成资产入库要有量化自审。** 〔条件：3D｜审片〕 网格指标、多方向渲染、线框、姿势测试格、动作抽帧；平台预设名不可信，套用前先抽帧看。（b612-slice，M45）
- **L60 找素材先把文案翻成镜头描述，再按本地 → 开放素材库 → 生成逐级找，每条留来源与许可。** 〔条件：素材检索、3D｜规划〕 抽象文案直接搜不到东西，先写成具体镜头（主体、动作、环境、景别、运镜、时长）再翻成检索词，英文词为主。操作演示、产品、本人出镜只在本地找（H2）；“世界的镜头”常在开放素材库找得到（H1）；都没有才生成或代码画。每条素材先看懂它在前后镜头之间承担什么再入序列，下载即写 manifest。见 lessons-backlog L60 细则。（外部 asset-discovery，2026-10-30 收录；asset-discovery-poc，2026-10-30 验证）

## 四、参考复刻与几何

- **L22 测量工具先在已知答案上校准。** 〔通用｜审片〕 一个数决定全片的测量（如投影角），先用合成图测一遍。（library-3d，M35） 验收脚本同理：每个检查项故意制造一次失败（删一个场景、写错一个转场、用一个缺字），确认它真的会红；外部的 qa 曾经全绿，其实根本没执行转场代码。（外部 huashu-art-motion）
- **L25 “看着不对”先量，再改。** 〔通用｜审片〕 角色像离地，量出来几何是贴地的，真正原因是低角度光下缺接触阴影。（b612-slice，M47）
- **L20 体量先对位，再做动画。** 〔条件：复刻｜执行〕 按参考图同比例、同机位渲染落成状态，与原图并排或半透明叠加，逐块对照后再出关键帧。（library-iso，M20）
- **L21 用户给的角度先量再解释。** 〔条件：复刻｜规划〕 “约 45°”可能指平面转角或俯角；拿参考图实测均值核对，在第一条回复里说明采用的解释。（library-iso，M23）
- **L23 逐帧断言，并按“来源 × 外观”归因。** 〔条件：复刻、3D｜审片〕 抽几帧会漏掉运动中的穿插；按对子归类后问题会自己分组。（arc-axo，M30）
- **L24 “每一帧都要满足”的约束写成判据让脚本搜。** 〔条件：3D、物理｜执行〕 路径先平滑求好看，再投影到硬约束，最后轻平滑一次，逐帧断言。（b612-slice，M52）

## 五、质感与画面

- **L54 “一眼 AI 味”主要有三个来源，开工前先锁住。** 〔通用｜规划、执行〕 ①每镜换一种画风的拼贴；②蓝紫渐变底、深紫星空、霓虹青紫光；③代码画的 Q 版小人、白壳机器人、给金币和小球加脸。对策：开工前写三行画风锁（画风一句话、色板 3–6 色、角色走哪条路），所有片段共用同一套色；人和拟人角色走生成帧 + 代码合成，过不了角色检验就只出手、背影、剪影，或让物靠形状和动作来演。粗糙的角色比没有角色更差。检验项与蓝紫标定见 lessons-backlog L54 细则。（外部 huashu-art-motion）
- **L55 镜头动作是标点：每镜同一个动作就是 PPT，不论快慢。** 〔通用｜规划、执行〕 每次动镜头前先答三问：观众这一刻该看哪、当前景别看不看得清；这一下是过渡还是重音；上一镜做了什么动作。看得清就不动，画面自己在动时停住；过渡用缓推、横移、拉远，快推、砸入、甩镜只给揭晓、反转、关键数字、笑点；推进去之后要拉出来、横移开或硬切换景别。参数与密度见 editing-grammar EG-25、EG-26 与第四节，镜头时长同理，等距快切读成零碎组接。外部反例与时长例见 lessons-backlog L55 细则。（外部 huashu-art-motion；idol-fx-mid v4）
- **L26 质感瓶颈先查光照和渲染管线，再查资产。** 〔条件：3D｜审片〕 判断问题来自哪一层，同时渲“只换渲染器”和“只改材质”的对照，测高光选侧光帧。（b612-slice，M54）
- **L27 产品片：有可运行 demo 时，重建 DOM 并复用原 CSS 是一种选择。** 〔条件：产品片｜规划〕 一致性由原 CSS 保证，镜头与标注由代码控制；文案和数据从 demo 源码取。先在浏览器里跑一遍 demo 拿真实布局和坐标。叠层坐标按渲染后的 DOM 实测，不写死。（saas-launch 两版，M57、M62、M68）
- **L28 色调跟着产品走。** 〔条件：产品片｜规划〕 浅色产品配浅色大字场景，避免亮度硬跳。（saas-launch 两版，M69）
- **L29 英雄镜头可以先给结果，再回到起点。** 〔条件：产品片｜执行〕 同一份状态函数用一个虚拟时刻求出成稿态。（saas-launch-v2，M63）
- **L58 画风迁移学的是画家怎么画，不是名作里画了什么。** 〔条件：画风｜规划〕 并看至少 3 件不同作品，记下笔触与材料、色彩关系、用光、造型、空间组织，再写出和最近邻风格的两点区别；名作里的人物、物品、布局不随风格进新片，构图按这个风格自己组织画面的方式为新题材重做。“这种画在现实里怎么做出来”就是渲染器的规格；角色也要过同一个渲染器，否则像贴上去的剪贴画。验收拿原作接触表和自己的静帧并排看。做法与分级见 lessons-backlog L58 细则。（外部 huashu-art-motion）

## 六、审片与验收

- **L30 审片分层，从便宜到贵。** 〔通用｜审片〕 线框调试图 → 正式静帧网格 → 全片联系表 → 关键时刻逐帧条，每层只回答一个问题。不为看一处问题反复渲染全片。（bell-machine，M18）
- **L31 先测一次渲染耗时，再决定迭代粒度。** 〔通用｜规划〕 全片很快就迭代全片草稿；静帧两轮之后就渲半分辨率全片看节奏。（bell-machine、saas-launch-v1，M19、M60）
- **L32 验收要有一项看连续帧。** 〔通用｜审片、交付〕 静帧、每秒联系表、定格节奏检查都看不到逐帧抖动；成片跑乒乓帧检测，改动段按全帧率抽帧拼图。有运动模糊的片子，再抽局部运动最快的几帧放大看（`mg-qa/fastframes.py`）：样本不足的分层残影，联系表和乒乓检测都看不出。（saas-launch-v2，M66；claude-showreel 第 224 帧）
- **L34 自动检查是线索，不是判决。** 〔通用｜审片〕 先归因再决定改不改，不为让检查变绿去改画面；最终听感按人耳。能升格为拦截门禁的，只有在用户表过态的片子上单独就能把正负例干净分开、阈值两侧都有余量的指标，再加不需要标定的事实类硬伤。本机门禁只有镜头内快速运动帧占比（G3），阈值只在解说片上标定过，抒情慢片读红只当“去看”；口径、硬伤判法与标定数据见 lessons-backlog L34 细则。（b612-slice，M55；外部 huashu-art-motion；marunouchi-lyric 系列、let-me-paint 试跑，2026-10-26）
- **L35 调试代码与防御性补丁随根因一起收回。** 〔通用｜交付〕 保留的必须写明防什么、怎么验证过。（saas-launch-v2，M67）
- **L36 渲染崩溃先清场、单因素复现，再下结论。** 〔通用｜执行〕 不可复现就记“不可复现”，不写成因果。（saas-launch-v2 复盘）
- **L56 交付前让没参与制作的 Agent 只看成片挑问题；自评分以独立复核的较低者为准。** 〔通用｜交付〕 审片人不读代码和过程，只看成片和抽帧，按时间码记问题、根因、改法、复验；除了画面，还要查逻辑和数字口径（“涨了 9 倍”应为“涨到原来的 9 倍”、两张图的同一个终点价对不上、连线连错层）。外部多次抓到制作者自看 3 轮都没发现的问题（同一动作在每段重做一遍、穿帮的两个头、字形读错）；自评比独立复核平均高约 10 分、最多 17 分。（外部 huashu-art-motion；本机 claude-showreel 未做，第 224 帧分层残影漏进成片）
- **L33 用和参考片同样的版式审片。** 〔条件：复刻｜审片〕 字号这类全局问题只有并排看才发现。复刻视频时把成片和参考片按同一时刻成对抽帧左右并排，按节拍 → 构图 → 配色 → 字体 → 运动状态看，修最大的一处再渲一次。SSIM 只决定先看哪一对：它看不出标题写错、节拍顺序错，还会惩罚用户要求的改动，分数首先反映节拍是否对齐；校准数字见 lessons-backlog L33 细则。（city-love，M43；外部 OpenDesign Motion 的方法，`ref-match/compare_video.py` 本机重写，2026-10-29）
- **L52 生成素材先量明暗关系，再定 matte 策略。** 〔条件：抠像、生成｜执行〕 主体比背景亮（烟雾、逆光水滴）才走亮度阈值；主体比背景暗（墨、剪影）时亮度 key 会挖空主体、把背景的亮斑 key 进来，改用静止背景差分（背景 193 帧不动时覆盖干净）。毛边要另拆 core / fringe，否则运动时闪。（deepseek-no-camera） 主体暗、轮廓有亮顶缘、背后是一条平滑辉光带（逆光地平线）时，按行中位数或绝对亮度都会把辉光算进主体；用局部反差（亮度减大半径高斯模糊）找顶缘高光，再逐列向下填到地平线，matte 才贴住轮廓。（lensless）
- **L53 遮幅片的活动区原点只定义一次。** 〔条件：遮幅｜执行〕 画面层、字幕层、遮幅必须共用同一个 y 原点；只给字幕按 2.39 活动区定位、画面从 y=0 起画，会让每个镜头切顶一角、字幕整体偏低、底部多一条黑带，而静帧和联系表都看不出，只有逐行量边界亮度才暴露。（deepseek-no-camera）
- **L51 后期手法要验证、又没有现成素材时，用 3D 渲染自产底片。** 〔条件：3D｜规划〕 同一个场景按需要分别渲出晃动版、绿幕版、低帧率版、同机位遮罩，再对其中一版做模拟色偏。处理前后有确定的基准，数字可以测，而且免费、可复现；代价是素材干净，内容差异大、真实噪声多的实拍情况测不到。（code-to-cinema）
- **L57 模板和参数化片段要换不友好的输入再审一次。** 〔条件：模板｜审片〕 示范片的输入是挑过的，管线给的不是：外部 8 种示范片都过了审，参数化之后只有 3 种能直接用（刻度取整撒谎、被标注的类目没名字、大数字压线头、字没打完相机就走）。每个模板至少喂负数、小数、超长标题、竖屏、无图、透明底各一份；版面放不下时要有退路，依次缩字、折行、让位，最后才告警，只在样例长度上调好的版式一碰真实口播就破。（外部 huashu-art-motion）

## 七、声音

- **L44 响度和真峰值在编码后的成片上测。** 〔通用｜交付〕 中间 wav 的峰值不算数；没有人耳试听要在交付里写明。（多个案例，M15、M43）
- **L37 卡点用实测起音，不用 BPM 网格推算。** 〔条件：配乐｜执行〕 时间换算用“采样数 / 采样率”，不用近似值；音频硬切处会出现假起音。（bell-machine，M10–M12）
- **L38 先拿到配乐、实测节拍，再排分镜。** 〔条件：配乐｜规划〕 段落边界写成“小节 + 拍”，吸附到乐句；需要缩短就在小节线上整段剪。（saas-launch-v1，M58） 复刻时沿用参考片原声、成片时长又不同：在场景边界附近的安静点切开，逐段用 `atempo` 调到新段长，音乐限 0.8–1.25×、有人声限 0.95–1.05×，段间 20–50 ms 交叉淡化，开头淡入 0.15 s、末 1 s 淡出；超出范围的段保持原速裁尾，交付里写明哪几段对不上。（外部 OpenDesign Motion）
- **L39 用户给的配乐不改时，只动音效总线，并交付证明。** 〔条件：配乐｜交付〕 成片音轨减去音效，与原曲做相关。（bell-machine，M13）
- **L40 音效由事件驱动。** 〔条件：音效｜执行〕 时刻等于事件时刻，响度跟强度，声像跟画面位置。（bell-machine，M14）
- **L41 TTS 一句一核。** 〔条件：配音｜执行〕 生成后立即 ASR，发现一类错误就全量排查同类句子。（saas-launch-v1，M59）
- **L42 声音选底子，不改信号。** 〔条件：配音｜规划〕 要童声就找本来是孩子的音色，用文字描述语气，不用变调硬改。（b612-slice，M56）
- **L43 “音频不做任何处理”交付时，用流拷贝封装并用解码 PCM 的 MD5 证明。** 〔条件：配乐｜交付〕 比相关系数更强：采样数和 MD5 都与源一致才算通过；同时给一个播放器兼容的无损版本（如 MOV + ALAC）。（marunouchi-lyric）

## 八、付费与交付

- **L48 交付目录开工即约定，边做边同步。** 〔通用｜规划〕 （saas-launch-v1，M61）
- **L49 交付说明里每条“已验证”都对着产物回读。** 〔通用｜交付〕 打开文件看内容、`ls` 看产物、重跑一次检查。（library-iso、saas-launch-v2，M73） 上屏或写进交付表的验收数字（抖动、ΔE、落键误差等）直接读处理脚本输出的 JSON，画面与交付表同源；离线算出的数字与渲染后实测的数字分开写。（code-to-cinema）
- **L45 付费调用三件套：官方定价页报价、单一入口拦截、余额差记账。** 〔条件：付费｜执行〕 失败调用也记账；网上的额度信息先核发布日期。（b612-slice，M51）
- **L46 付费调用前按对应 Skill 规则确认，即使预算小。** 〔条件：付费｜规划〕 用户没有预先授权时，先用一个问题确认来源和预算。（saas-launch 两版，M72）
- **L47 生成后先审片再用。** 〔条件：生成｜审片〕 逐张联系表看动作和解剖细节；没按 prompt 做时先看能否靠后期对齐，再决定重跑。（city-love，M42） 复用旧镜头同样如此：分镜稿写“复用”时附实际帧，按文件名和旧描述写的声明会悄悄漏掉必须重拍的镜头，一次审片查出 13 处不符。（qingniang-v4-audit） 把人物或风格判成“问题”前，先对照设定板：板上本来如此的是作者的设计，改它要先问作者，不要直接出图试错。（qingniang-v4-audit）
- **L50 同题多模型对比时，后跑的一方不读先跑的产出。** 〔条件：对比实验｜规划〕 共享的只能是工作区经验，不是答案。（saas-launch-v2，M71）
