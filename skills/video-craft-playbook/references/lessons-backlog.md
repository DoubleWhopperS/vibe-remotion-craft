# 候补层：等第二个案例的经验与坑

常驻层（[craft-lessons.md](craft-lessons.md) ≤ 60 条、[pitfalls.md](pitfalls.md) 按工具分组设上限）满了以后，新经验和新坑先写在这里：不丢，也不挤占常驻层。这里的条目和常驻条目一起被 `playbook.py brief` 按标签取出，标“候补”。规则见 [writeback.md](writeback.md) 第一节第 4 条。

- 格式与常驻层相同：经验条目 `- **L<n> 标题。** 〔通用或条件：标签｜阶段〕 正文（来源，日期）`，L 号从全局最大号 +1 取，晋升时原号带走，引用不断，其他文件用「lessons-backlog L<n>」引用；坑按工具分组，分组标题带工具标签 `〔标签〕`，写现象 → 修法（来源）。
- 晋升到常驻层的条件：第二个不同题材的案例在“起作用”栏记了它；或没参与制作的审片者回溯判定某个缺陷本可被它防住；或用户反馈与它一致；或推翻了常驻层的现有说法。只有一个来源的留在这里。
- 归纳：`playbook.py status` 在候补 ≥ 15 条、最老一条超过 60 天、或上次归纳以来关闭 ≥ 5 个案例时提示；`playbook.py consolidate` 列出可晋升候选、计数与容量，按 writeback 第一节第 4 条的归纳清单处理，做完把下面的日期改成当天。
- 上次归纳：2026-10-30
- 外部蒸馏（只有外部证据、本机未验证）的条目从这里起步，本机验证后再升。
- 常驻条目超过 300 字时，结论和规则留在常驻层，参数、外部数字、反例与排查过程下沉到本文件「常驻条目细则」，条目写成 `- **细则 L<n>。** …（来源）`，常驻条目末尾用「lessons-backlog L<n> 细则」指回。

## 经验候补

- **L61 解说、科普片先写镜头表，每行一个物加它自己的动作。** 〔条件：讲解片｜规划〕 每行一个物（名词）加它自己的动作（动词，不写“出现 / 显示 / 淡入”），写不出物的那一镜先别做；抽象概念找一个具体的物来演。开头 3 秒是一个人或物在做一件和题目有关的事，不是标题；结尾落在主物的一个动作上，不收在居中金句卡；全片一个具体例子贯穿；文字主导的镜头不超过三成；相邻两镜换构图和镜头，不换画风。（外部 huashu-art-motion，2026-10-26 收录；2026-10-30 自 task-lenses 第 9 问移入候补，本机未验证）

- **L62 「高级感」先找一个意念，再找素材。** 〔条件：产品片｜规划〕 一个隐喻一种材料，版本号或名字本身当主题（以多种材质反复出现，不配形容词）；能力词藏在道具上让观众读到，不打大字；近单色，唯一的饱和色只给母题；2–3 帧静物快闪与 1–3 s 停留交替；图形匹配（主体不动、背景翻页），定点物要有来由（前一段出现过，或就是下一段的主角）并服务母题，否则读成误留的残件（llm-launch-agate：无来由的反写铅字被用户判「像误删的败笔」，换成下一段的放大镜、镜下对准每页最小的字后成立）；收束走实物 → 抽象 → 空白 → 字标；母带安静，低频只在意义点出现，剪辑吸附乐句起点而非鼓点。差距可量：亮度中位、饱和度中位、切点数、LUFS 与参考片并排。（Kimi K3 发布片拆解 + llm-launch-agate 复刻，2026-10-31；复刻版尚无用户评价）

- **L63 排时间线先划停留帧，再排动效。** 〔条件：产品片、讲解片｜规划〕 承载信息的元素落定后静止 ≥1 s 再切，停顿给字标和关键信息，不给普通内容卡；开场主体走完一条 ≥3 s 的动作弧；模拟打字、筛选、点击按真人操作速度，观众要能跟着做一遍；批量入场收尾静止约 0.5 s。作者整支宣传片的六次节奏反馈全部指向放慢，没有一次嫌慢，初版宜预留停留帧预算。（外部 video-shotcraft aesthetic-rules R1–R3，2026-11-01 收录，本机未验证）

- **L64 光效只给主角一次，飞入元素落进真实槽位。** 〔条件：产品片｜执行〕 扫光、泛光、glint 不群发，一镜最多给主角一次，并裁进承载元素的圆角；批量入场的动感交给运动本身。飞入、过滤后归位的元素，终点是页面布局里的真实格位，不悬浮在页面上方。判例：逐卡闪光两次被用户否决，卡片悬浮版近乎整文件重写。（外部 video-shotcraft aesthetic-rules Q4、Q9，2026-11-01 收录，本机未验证）

- **L65 卡点管时机，不放大幅度。** 〔条件：配乐｜规划〕 作用于整画面或相机层的节拍冲击（整画面缩放泵、震屏、闪帧、负片帧）全片 ≤3 处，钉在最强的几个 hit 上、相邻间隔 ≥16 拍；其余拍点只动主角元素层。kick 命中表是候选池，不是触发器；一张卡的一次连发算一个名额。判例：逐拍全画面泵被用户判「镜头随节奏抖动」。（外部 video-shotcraft aesthetic-rules R4，2026-11-01 收录，本机未验证）

- **L66 画面动作配它自己的声音，样本裁到与动作等长。** 〔条件：音效｜执行〕 打字配键盘、逐条落入配逐个 pop，泛用 swoosh 盖不住有辨识度的动作；长样本按画面段落截断，不拖过动作结束。峰值低于 -12 dB 的轻音素材，音量系数给到 1.0 仍可能被配乐盖住，渲染后测峰确认听得见。（外部 video-shotcraft aesthetic-rules S4，2026-11-01 收录，本机未验证）

- **L68 从参考片借的科技感元素，各自绑定画面里的一件事，做成过程；质感层只盖画面，信息层在上。** 〔条件：复刻、预告片｜执行〕 点阵、网点、终端、辉光管、检测框不做全片滤镜：点阵只出现在扫描线扫过、实物凝成这类有语义的时刻，每刀 b-roll 的读数讲这一刀发生的事；读数用真数据（原曲频谱、累计打击、当前变速），不放随机数；参考片里服务它自己叙事的元素不搬。网点一类印刷质感只盖实拍，歌词、HUD、人脸框都在其上，且与歌词同一套质感。判例：五刀 b-roll 整刀点阵化，导演：「这只是一种策略……不要把所有 b-roll 都渲染成点阵」；网点盖住歌词与辉光管被要求挪到下面。（idol-trailer v4–v6，2026-11-03，工作区 methods 76–77）

- **L67 预备动作与蓄力先算像素，再算比例。** 〔通用｜执行〕 教科书比例（预备约为主动作的 20–30%）在拉远机位下换算成的像素位移过小，肉眼看不出；作者两档小幅度用户都无感，放大约 12 倍才被认出。渲染后正常速度回放，不逐帧也能看出蓄力才算数。（外部 video-shotcraft 卡 deck-deal-flyin 已知坑，2026-11-01 收录，本机未验证）
- **L69 网页动效要真运动模糊时，在快门窗口内多次渲染，再到线性光里平均。** 〔条件：运动模糊、网页渲染｜执行〕 前提是画面为 t 的纯函数：它不碰 DOM、Canvas、WebGL 的区别，全图层一起模糊，亮色拖影也不发脏。只渲快门开启的窗口，样本数按段落给：匀速段 6，普通 16，铺屏这类边缘每帧移动上百像素的 72。代价随样本数线性增长，路径追踪段最贵。实现见工作区 `temporal-supersample/`。样本间距约等于“边缘每帧位移 × 快门 ÷ 样本数”，大了就出分层残影：第 224 帧整词约 2.5 帧内压扁，16 个样本间距约 10 px，成片可见台阶；铺屏圆盘 24 个样本有同心色带，改 72 后成连续渐变。可接受的间距上限（约 3 px）是推断，未系统标定。（claude-showreel，2026-11-07）

- **L70 three.js 要写实或电影感时，按层提质，让大气替你藏弱项。** 〔条件：three.js｜规划〕 顺序：色彩管线（HDR 半浮点、颜色贴图 sRGB、数据贴图 linear、选定 AgX / ACES / Neutral）→ 一个强光源（逆光或侧逆光）→ 距离与高度雾拉开前中远景 → 现成贴图或烘焙 AO → 统一色调 → 抗锯齿；之后才上体积光、SSR、SSGI。雾藏远景、暗部藏贴图精度、单色调藏资产色差。选 AgX 时按显示亮度定色板：沿用 Linear 下的场景值，暗场会被抬成中灰（storm-pirate：压暗约 2.5 倍、AgX 后补 `pow 1.2–1.3`）。光怎么做见 L75。（外部：Web3D 精选第 6 期拆帧；本机验证 storm-pirate v1–v3，2026-11-09，用户认可终版）

- **L71 逐帧离线渲染 three.js 时，时间累积类效果换成帧内多样本。** 〔条件：three.js、网页渲染｜执行〕 TRAA、TAAU 持有历史帧和上一帧相机矩阵，依赖上一帧的运动模糊和时间降噪同理：并发分段、跳帧审片时读到的“上一帧”不是时间上的上一帧，违反 L9，单帧看不出（推断，源码核对 r186 `TRAANode`）。→ 同一帧内快门窗口取 K 个时刻 + Halton 亚像素抖动，渲到 HalfFloat 目标累积后再走后期，只截一次图。实测（storm-pirate）：K=24 约 0.2 s/帧，单样本 GPU 约 4 ms、截图占大头；每样本截图慢约一个数量级，且在 8 位色调映射后平均。（threejs-look-research 推断；storm-pirate 验证替代做法，2026-11-09）

- **L72 高保真 3D 先“找”后“做”：主体按现成模型 → 扫描材质 → 生成 → 程序化的顺序找。** 〔条件：3D、three.js｜规划〕 船、建筑、载具、角色这类观众盯着看的主体，先检索现成资产（atlas H3：Sketchfab 检索 API 匿名可搜，筛可下载与 CC BY / CC0；Poly Haven CC0 模型与扫描材质），程序化只做环境与动态（海、云、雨、粒子）。现成模型进 Blender 是“完善”不是重建：烘焙骨骼、统一朝向与尺度和水线、剔除异常部件、`ray_cast` 定挂点、补叙事部件、压暗做旧、按名字拆出要动的部件。判例：v1 bpy 手搓船被用户判“几何体堆叠”，换现成船模后同一管线过关。（storm-pirate，2026-11-09）

- **L73 和参考片并排时按四项列差距：主体资产、光的结构、纵深体量、主体与环境的互动。** 〔条件：复刻、3D｜审片〕 每轮同机位抽 3 帧与参考并排，四项逐项补，一轮只动一两项便于归因；交付前就做，不等用户说“差很多”。storm-pirate 依次补：现成船模（主体）→ 云隙光源、遮挡图光柱、水面亮带（光）→ 光源两侧三层岩壁框住光（纵深）→ 船头持续破浪（互动）。光和纵深两项用户没点名，是并排后才看出的。（storm-pirate，2026-11-09）

- **L74 真实录音做音效：铺底与事件分总线，事件让位、截前导、留空档。** 〔条件：音效｜执行〕 风暴海、暴雨这类铺底是满频宽带，直接叠事件会被吞（近雷低频只 +0.8 dB）。→ 事件包络驱动铺底让位（约 -7 dB，起 15 ms、放 600 ms）；素材按主冲击（包络最陡上升点）对齐，并从主冲击前约 30 ms 截掉前导，否则前导提前进入、抬高事件前的电平；相隔约 1 s 的两个事件，前一个的长尾截短。盲调参数前先拆总线逐 50 ms 测电平。（storm-pirate，2026-11-09）

- **L75 three.js 光的结构：一个强光源 + 遮挡图光柱 + 主体比背景暗。** 〔条件：three.js｜执行〕 光柱用 1/4 分辨率遮挡图做径向累积（天空只画光源，实体用黑材质，海面复用波浪顶点着色器）；直接模糊 HDR 亮部会把灯笼拉成射线。径向长度约 0.55、衰减约 0.955，否则桅杆阴影拉成贯穿全画面的黑杆。逆光雾只留在光源附近，主体推近到雾薄、比背景暗（参考片同理）；暗背景前的透明面片硬边团块会读成黑洞。（storm-pirate v2–v3，2026-11-09）

## 坑候补

### Remotion（4.0.x）/ 浏览器渲染 〔网页渲染〕
- 多个组件各建 WebGL 上下文，场景在不连续帧之间重新挂载时，新画布首帧常在合成前就被截图：成片出现空白画布的单帧，静帧正常，同片 Canvas2D 无此问题。→ 每个渲染标签页一个离屏 WebGL 上下文，画完同步 `drawImage` 到组件自己的 2D 画布。（llm-launch-agate 第一版，2026-10-31）
- 视频 `<Sequence>` 边界用 `round(s×fps)`、场景用 `t >= a && t < b`：11.21 s × 24 = 269.04 → 269，边界帧两边都不画，成片多一帧空底。→ 两边统一取「第一个 t ≥ 边界的帧」`ceil(s×fps − ε)`。（llm-launch-agate，2026-10-31）
- 整段缓推的画面里把 2600 px 原图缩到几百像素显示，截图偶发整块未光栅化（3 处 5 帧，乒乓帧段长 1 抓到）。→ 换成显示宽 ×2 的小图后为 0（根因推断）。（llm-launch-agate，2026-10-31）
- 宿主进程连不上 WindowServer、又不想重启时：系统 Google Chrome（156，`--headless=new`）里 rAF 正常，Remotion 配 `setBrowserExecutable` + `setChromeMode('chrome-for-testing')` 即可渲染，HtmlInCanvas 与着色器转场照常。（code-to-cinema，2026-10-24；2026-10-30 自 pitfalls 同条拆出）
- 3D 透视或放大镜头里的 UI 文字发糊、有像素方块，调景深和相机都无效：Chromium 按布局宽度栅格化合成层，再由 GPU 放大。→ 放大量走 CSS `zoom`（布局级缩放）而不是 `transform: scale`，纹理源 ≥ 显示尺寸 2 倍；改用 zoom 后取景坐标要按 zoom 换算，否则跑焦点。验证时逐帧裁剪放大看字边缘。（外部 video-shotcraft aesthetic-rules Q2，作者三轮返工，2026-11-01 收录，本机未验证）
- `<OffthreadVideo>` 没有 loop 属性，素材短于所在 Sequence 时播完冻在末帧，静帧抽在前段看不出。→ 按素材长度分段续播，段间交叉淡化。（外部 video-shotcraft `assets/lib/ClipCard.tsx`，2026-11-01 收录，本机未验证）
- `<Sequence>` 会重定子组件的帧号，再叠 `<CameraMotionBlur>` 内部的 Freeze，按帧号算位置的页面相机会采样到错帧，横向运动模糊错位穿帮。→ 按绝对帧编排的相机组件显式传入绝对 `frame`，不读 `useCurrentFrame()`。（外部 video-shotcraft 卡 deck-deal-flyin 已知坑，2026-11-01 收录，本机未验证）
- 开启多重采样运动模糊后，时间函数里的跳变变成单帧双重曝光：以 `cos` 起步的阻尼振荡在撞击瞬间跳变，字上出现灰色重影，单样本静帧看不出。→ `sin` 起步或加 2–3 帧起音；运动模糊要早点开着抽检。（claude-showreel）

### 生成视频 / 图像 〔生成〕
- 生成的群喊镜头常只有一次张嘴：两声口号只能对上一声，从素材 0 s 起用时嘴型晚 0.25–0.3 s，静帧看不出、配原曲才露馅。→ 逐帧裁出嘴部找张嘴帧，入点对齐人声起音；素材里没张嘴的那一声调入点解决不了，要重拍。（idol-trailer v6，2026-11-03）
- 按逐词对齐时间给唱段人声静音、只留字内：对齐把字尾标早时，拖长的尾音被切成静音，对口型模型在那段闭嘴，配原曲才露馅。→ 只静音第一个字之前和下一句开始之后。（idol-fx-mid，2026-11-02）

## 常驻条目细则

- **细则 L50。** 评估本手册有没有用，也按同题对照来做：同一天、同一环境、同一 prompt，唯一变量是加不加载本手册和工作区规则，每组至少 3 次；后跑的一组不读先跑组的产出。客观指标用同一套脚本：编码后响度与真峰值、快动帧占比（`motion_gate.py`）、色相族、乒乓帧、最快帧（`fastframes.py`）；主观部分盲评，评审不知道哪版来自哪组；同时记耗时与 token。
  - 反例（2026-11-07，claude-showreel 对比 10-05 无手册的 Opus 版与 09-27 的 GPT-6 Astra 版）：每组只有 1 支，相隔一个月，prompt 不全一致，工作区是之后才建的，评审又是制作者本人。只能确认三项改变来自手册与工作区规则：无手册的 Opus 版 -9.5 LUFS / +1.7 dBTP 削波，有手册版 -14.1 / -3.1；拍号事件表与误差表带出了句号落点被长尾盖住这个真缺陷；产物可复现、可复用。
  - 创意和技术野心归不到手册：圆点主角、句号收尾、HUD 在无手册版里同样出现，路径追踪与超采样模糊手册里没有。代价是出片约 1 小时，GPT 版约 8 分钟。
  - 证据在 `projects/2026-11-07-claude-showreel/process/skill-comparison/`。
