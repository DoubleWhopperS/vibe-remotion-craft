# 可剪信号：理解层要交给剪辑决策的数据

> 教材层：本文件允许推断条目，是剪辑类任务的通用手法与信号参考。回写只在条目末尾标“验证 / 推翻（案例，日期）”，不按案例追加条目；分层规则见 [writeback.md](writeback.md) 第一节。

后处理能做到多细，取决于对素材的理解产出了什么信号。只有“这段讲了什么”的摘要，就只能按段落切开拼接；有了逐词时间戳、节拍、主体轨迹、运动方向，[editing-grammar.md](editing-grammar.md) 里的手法才有触发条件。本文件定义这些信号的字段、时间基准和可靠性边界，作为理解端与剪辑端之间的数据约定，与具体软件和平台无关。

**验证状态**：2026-10-24 收录。运动、主体轨迹、每镜色彩统计三行在 code-to-cinema 中实测过提取与使用（见行内），其余字段为推断；各信号的提取能力见能力卡 G1、G2、G5。

---

## 一、通用约定

- **时间基准**：每条素材内部用源时间（秒，浮点）并记录源帧率；映射到成片时间轴时走时间权威（task-lenses 第三节），不在信号文件里写成片时刻。
- **一条素材一个信号文件**：以素材 id 为键，信号互相独立，可以只跑其中一部分。
- **置信度随数据走**：每个检测结果带 `conf`（0–1）。剪辑端按置信度决定是否使用依赖它的手法，例如主体轨迹置信度低就不做跟随重构图（editing-grammar EG-21、EG-52）。
- **来源可追溯**：每类信号记录提取工具、版本与参数，便于换工具后对比。
- **坐标**：空间量用归一化坐标（0–1，原点左上），与分辨率无关；需要像素值时按源分辨率换算。

## 二、信号清单

| 信号 | 字段 | 消费它的手法 | 提取能力 | 可靠性边界 |
|---|---|---|---|---|
| 镜头边界 | `shots[]: {start, end, conf}` | 素材库化、EG-05、EG-61 | G1、G5 | 叠化、闪白、快速运动会产生误检或漏检 |
| 可用区间 | `usable[]: {start, end, reason}` | EG-12、择优 | G5 + 人工或模型审片 | 只能剔除明显废片 |
| 镜头质量分 | `quality[]: {t, blur, exposure, shake, eyes_closed}` | EG-11、EG-12、EG-23 | G5 | 指标测不出“好不好看” |
| 逐词时间戳 | `words[]: {start, end, text, conf}` | EG-01、EG-02、EG-10、EG-50 | G2 | 目前 G2 只到句级，逐词需要支持词级对齐的 ASR；歌声识别差（G2） |
| 静音与停顿 | `silences[]: {start, end, db}` | EG-10 | D1（`silencedetect`）、E1 | 环境噪声大时阈值要按素材调 |
| 口误与重复句 | `disfluencies[]`、`repeats[]: {group, takes[]}` | EG-10、EG-11 | G2 转写 + 文本比对 | 依赖转写质量；重复的判定需要语义比对 |
| 节拍与段落 | `beats[]`、`bars[]`、`sections[]: {start, end, label}` | EG-04、EG-06、EG-64 | 本机 `audio-sync/beattrack_dp.py`（E1） | 用实测起音；摇摆节奏要专门跟踪（craft-lessons L37） |
| 能量曲线 | `energy[]: {t, low, vocal, high, onset}` | EG-06、EG-64 | 本机 `audio-sync/features.py` | 母带压得很满时段落间差异小，弧线要手写（task-lenses 第 8 条） |
| 主体轨迹 | `subjects[]: {id, track[]: {t, box, conf}}` | EG-20、EG-21、EG-52 | G5 | 遮挡、小目标、风格化画面不稳；要先平滑再用。单色主体可用颜色阈值质心跟踪，自产底片上覆盖 100%（code-to-cinema） |
| 显著区域 | `saliency[]: {t, point, conf}` | EG-22 | G5 | 画面里有多个主体时会跳 |
| 运动 | `motion[]: {t, dx, dy, speed}`（全局）、可选分区域 | EG-03、EG-24、EG-62 | G5（光流） | 低纹理、快速运动、闪烁处不可靠。全局位移可用 FFT 相位相关（加汉宁窗、避开运动主体区域）测出，code-to-cinema 用它报稳定前后 RMS |
| 抖动量 | 由 `motion` 高频成分派生 | EG-23 | G5、D6 | 难以区分刻意的手持感和意外的晃动 |
| 人脸与视线 | `faces[]: {t, box, gaze, conf}` | EG-20、连续性 | G5 | 侧脸、遮挡时丢失 |
| 每镜色彩统计 | `color[]: {shot, mean_lab, std_lab, wb}` | EG-40、EG-41 | D7 | 内容差异大的镜头统计不可比。同场景镜头间用均值 / 方差即可拟合 LUT（code-to-cinema） |
| 响度 | `loudness[]: {start, end, lufs}` | EG-43 | D1（`ebur128`） | 以编码后的成片为准 |
| 语义标签 | `tags[]: {start, end, labels[], embedding?}` | B-roll 匹配、EG-05、H2 本地素材检索 | G2（`video-intelligence`） | 模型理解会出错，关键匹配要抽帧核对 |

## 三、文件形态示例

```json
{
  "clip": "interview_a.mp4",
  "fps": 29.97,
  "size": [1920, 1080],
  "sources": {"words": "asr-x 1.2, word-level", "beats": "beattrack_dp.py"},
  "shots": [{"start": 0.0, "end": 12.4, "conf": 0.93}],
  "words": [{"start": 1.02, "end": 1.31, "text": "今天", "conf": 0.97}],
  "silences": [{"start": 3.80, "end": 4.62, "db": -42}],
  "subjects": [{"id": "p1", "track": [{"t": 0.0, "box": [0.41, 0.18, 0.22, 0.55], "conf": 0.9}]}],
  "motion": [{"t": 0.0, "dx": 0.002, "dy": 0.000, "speed": 0.002}]
}
```

字段可以按需增减；增减时同步更新第二节的表，让剪辑端知道每个字段的含义与边界。

## 四、剪辑端怎么用

1. 先跑理解，看信号覆盖率和置信度，再决定这条片子能用哪些手法：信号缺失或不可靠，就不用依赖它的手法。这本身就是选型的一部分（task-lenses 第六节）。
2. 决策结果写成时间线（切点、变换关键帧、转场及其动机、效果栈、音频分轨、字幕），渲染端只读时间线，不回头读信号。
3. 成片再跑一遍同样的理解，作为验收：字幕与逐词时间戳对齐、切点与节拍偏差、黑帧与跳帧、响度（G3）。
